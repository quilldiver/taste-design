# Taste Design 设计厨房

设计师工作室品牌官网。视觉主线：WebGL 着色器背景 + 三屏滚动吸附 + 首屏持续自转的 3D 图片环（RING，40 张作品卡围成一圈、俯角可随光标视差）+ 第二屏的 3D 卡片长卷（七类出品，恒定 90° 的鳍片 + 离轴透视，可拖拽 / 点击 / 左右键）+ 末屏的**泡泡池**（14 个品牌的 logo 玻璃球从窗口顶部落下、压在文案之前、堆在屏底，每颗球带着自己的倾角与滚动，指针可推开 / 抓起甩出），以及一个三栏式的**作品索引页**（左 一级+二级 / 中 三级 / 右 可长滚的图片流）。

> ⚠️ **发布源以单文件版为准**：线上站点直接发布 `taste-design.html`，**不再发布 Next 构建产物**。
> 原因是两份已经分叉了——Next 版还停在「3D 品牌球」阶段，没有泡泡池、没有卡片长卷的进出场状态机；
> 单文件版才是最终完成的那份。详见下方「双交付」。
> Next 的构建命令请在**你自己的终端**里跑——AI 助手的内置沙箱会拦截它写 `.next/` 目录。

## 三、作品索引页（`/works/<slug>`）

> **单文件版已不再暴露这一页**：`taste-design.html#/works` 那张独立作品页已删除，
> 作品只在「第 2 屏点击卡片」时以作品集形式就地展开（见 5.1）。下面这套三栏版式、
> 数据结构与滚动反推的两份实现（Next 版 `/works/<slug>` 与单文件版的隐藏宿主）
> 仍然共用，样式与逻辑没有变化。

版式来自《排版参考》：**左**是一级菜单（英文大字 + 中文小字）与内联手风琴二级菜单，**中**是当前二级下的三级列表（即作品名），**右**是图片流。没有二级 / 三级就整列不展示。

- **整页版心与末屏的 `.wrap` 同构**：`.wd-in` 用同一套 `max-width:1680px` + `padding-inline:clamp(1rem,4.5vw,2rem)`，三栏全部落在版心之内，左栏左缘与导航 logo 对齐。
- **三栏宽度**：三个真源变量 `--wd-c1:220px`（一级+二级**内容**宽）、`--wd-c3:clamp(176px,15.6vw,252px)`（三级**内容**宽）、`--wd-gap:80px`（两栏之间的净距）。剩下的宽度全部归 `.wd-feed` —— 它是三栏里唯一 `flex:1` 的项，所以**「把省下的空间给图片」不需要额外写规则**，反过来说也别给另外两栏加宽。实测图片列在 1024 / 1440 / ≥1680 分别占版心 43 / 55 / 60%。
- **字号**：一级中文 `14px`、二级与三级 `16px`（用户指定，窄屏同值）；一级各项之间 `8px` 间距。
- **选中项放大 1.25 倍**（`--wd-pop: .4s` 缓动，一级 / 二级 / 三级一致）：都用 `transform: scale(1.25)` + `transform-origin: left center` —— 从左边长出去，文字左缘（与 logo 对齐的那条竖线）不动。窄屏 chips 行改成 `center` 原点并各自收一档（一级 1.2、二级 1.15、三级 1.15）：横排时左右各长一半，得给邻项留位。
  > ⚠️ 缩放的**水平余量留在 `padding-right` 里**（= 内容宽 × 0.25，盒宽用 `calc()` 算）。因为 `.wd-nav` / `.wd-list` 都是纵向滚动容器，`overflow-y:auto` 会把 `overflow-x` 强制算成 `auto`（写 `visible` 无效，`overflow-clip-margin` 实测对 `hidden` 也不生效），超出内容盒的部分会被裁；而**裁剪边界是 padding box**，所以把余量放进自己的 padding 就能画出来。代价是图片列在 1920 下由 1064 → 1001px。
  > **二级多一层麻烦**：`.wd-l2` 自己就是 `overflow:hidden`（手风琴必须裁），所以它的 padding box 才是裁剪边界，**用不了 `.wd-nav` 外侧那 55px**。于是 `padding-right` 也从 `.wd-l2` 自己的 padding 出（同样 `.25`，内容盒 199 → 144px，缩放后盒宽 180px，右缘离裁剪边界还有 19px）。这层 padding 是**向内缩**，不占外部空间，所以 `.wd-list` / `.wd-feed` 的宽度不受影响。
- **二级菜单是手风琴**：展开 / 收起用 `grid-template-rows: auto 0fr ↔ auto 1fr` 过渡（`--wd-acc`），不用猜内容高度；收起时同时把 `visibility` 关掉，否则 0 高的面板里那些按钮仍会被 Tab 到。
- **排列顺序 = 一级菜单 → 二级菜单 → 三级（作品）**，而且这个顺序**就写在 `WORKS` 数组本身**（唯一真源）。图片流直接 `WORKS.map()` 铺出来，所以「滚到底自然接下一个作品」是数据结构的性质，不需要任何排序 / 拼接逻辑。`WORKS_BY_SEC`（某个一级下有哪些作品）是从它按 `sec` 过滤**派生**出来的，不再手工维护第二份 —— 两份真源正是下面那个坑的成因。
  > ⚠️ 曾经的坑：`WORKS` 是按**原作品集页码**升序排的（P4 → P116），而菜单的二级顺序是另一套，两边一脱节图片流里的二级就会来回跳（看起来就是「顺序很乱」）。实测 **7 处反跳**：Activity 的「品牌活动 → 城市品牌活动 → 品牌活动」（2 处）、Brand 的「餐饮 → 商业 → 餐饮」「宠物 → 商业 → 餐饮」「首饰 → 宠物」（4 处）、Packaging 的「护肤 → 餐饮」（1 处）。现在数组本身按菜单顺序重排，**物理顺序就是菜单顺序**，7 → 0。
  > ⚠️ `work.id`（`w05` 那类）里的数字是**原作品集页码编号**，只是稳定标识符（React key / DOM 标记），**与数组下标无关** —— 重排后 `w05` 落在下标 8。要定位原始出处看 `pages` 字段。
- 反过来，**滚动位置是唯一的状态源**：菜单高亮由滚动位置反推（判定线在视口高度 42% 处）。这样点菜单跳转与手动滚动永远不会互相打架。
- **三级菜单「切换」有过渡**（上下滚动 + 渐隐渐显）：切组（换一级 / 换二级）时新内容从「来的方向」滑入 + 淡入，逐条错峰 `38ms`。方向跟着浏览方向走 —— 往下浏览从下方升上来、往上浏览从上方降下来（`data-dir` 只切 `--wd-l3-dy` 的符号：`18px` / `-18px`）。**只在切组时播**，同组内点不同作品不播（否则每次点都会闪一下）。
  > ⚠️ 动画挂在 `li` 上、不挂 `.wd-l3b`：按钮自己用 `transform: scale()` 做选中放大（1.25），两处 `transform` 落在同一个元素上会互相覆盖（后写的赢）。
  > ⚠️ 两个交付版的「重播」机制不同：**Next 版**切组时 `li` 的 `key`（作品 id，全局唯一）全变 ⇒ React 卸载旧的、挂载新的 ⇒ 新 `li` 一挂载就播 CSS 动画；**单文件版**是「全量 52 个 `li` + `hidden` 切换」，元素从不重新挂载 ⇒ 必须在 `markList()` 里**手动重播**（`animation:none` → 强制回流 → 恢复），否则只有进页那一次会动。
  > 方向在 Next 版里用「渲染期比较上一次的 `workIdx` 并 `setState`」（React 官方的写法）拿到，保证渲染 li 时方向已是新值；单文件版则在 `setActive()` 里按 `i > workIdx` 记一个 `l3dir`。
- 图片流用 `<img width height>` 占位、`loading="lazy"`（仅首图 eager），避免未解码时偏移表算错。
- **作品标题下不显示原作品集页码**（`P7-P9` 那类只在 `works.ts` 里留着当溯源标记）。
- `<1024px` 三栏改三行横向 chips，激活项会自动带进视野。
- **图片流上下边缘的渐进模糊**（Liquid Scroll 那一套，只在这一页）：浏览器没有「渐变 blur」，所以用 **6 层 `backdrop-filter` 叠出来** —— 每层 blur 固定（9 / 7 / 5.2 / 3.6 / 2.2 / 1 px），靠 `mask-image` 决定它从边缘起「能活多久」（最糊那层只覆盖最外 30%，最轻那层铺满全带）。带高 `--wd-lq-h: clamp(56px, 8vh, 100px)`。
  > ⚠️ 每层 blur 必须**递减**：`backdrop-filter` 是串联的（后一层模糊的是前一层的输出），等强叠 6 层会把模糊度乘成 √6 倍，边缘糊成一块死色。
  > ⚠️ 覆盖层必须放在**滚动容器外面**，放里面会跟着内容滚走，用 `sticky` 又会占文档流。`pointer-events:none` 保证不吃点击与滚轮。
- **上下两带的挂载层级不同**：**上带** `.wd-lq` 在 `.wd-feed-wrap` 里 → 只盖图片列；**下带** `.wd-lq-bot` 挂在 `.wdetail` 一级 → **横跨整个视口、压在三栏所有内容之上**（`z-index: 6`，实测带子宽 = 视口宽 100%，层叠探测 9 个点全命中它）。两条带共用 `.wd-lq-band` 那套层参数，只是容器不同。
  > 为什么不把上带也整页化：左栏一级菜单从 y≈116 就开始，而顶部带占 y=80~166 —— 整页化会直接糊掉「Logo 那一项」。下带在 y≈994~1080，桌面下左栏底部没有任何内容（7 个一级 + 展开的二级最高约 446px），整页化只让**背景**跟着一起渐隐，不会糊到字。
  > ⚠️ `.wdetail` 必须自带 `position: relative`：下带靠它把 `absolute; inset: 0` 锚在「整整一屏」上。不加的话会一路往上找到 `main`（同为 relative），`bottom: 0` 就落到整份文档的最末尾。
- **顶部另加一层黑色渐变，且只在「往下滚过」之后出现**（`.wd-feed-wrap.is-scrolled`，由滚动反推那一次 rAF 顺手切）。阈值取**第一个作品的 `offsetTop`** 而不是 0 —— 进页时图片流本身就带着 `offsetTop-10` 的偏移（logo 页是 10px），拿 0 判定会让首屏一进来就挂黑幕。
  > **顶部整组随滚动淡入、底部常驻**：静止时图片流顶上就是第一个作品的标题，常驻会一进页就把它糊掉；滚过之后顶上确实压着内容，模糊才成立。底部相反 —— 内容永远延伸到视口下方。
  > ⚠️ 淡入**不能写成 `.wd-lq-t { opacity: … }`**：`opacity < 1` 会把该元素变成 backdrop root，子孙的 `backdrop-filter` 就只采样它自己（空内容），模糊整体失效。所以让每个 `span` 自己 `transition: opacity`（实测 `opacity:.5` 时边缘能量 5.1，介于「全模糊 3.4」与「无模糊 11.0」之间，证明模糊仍在工作）。
  > 性能：真实 GPU 下 12 层 backdrop-filter 对滚动帧率**无可测影响**（Apple M5 无头 Metal 后端，开 / 关都是稳定 60fps）。软件光栅（SwiftShader）下才会掉到 30fps —— 那是无头沙箱的假象，不代表真机。`opacity:0` 的层浏览器会跳过绘制，所以静止时更省。

## 四、首页第 1 屏：3D 图片环（RING）

参数不是估的，是照 **Framer Marketplace / RING 的原版实现**逐项量出来的（原版 demo：<https://ring.framer.media/>）。原版 @1440×900 的实测值：

| 参数 | 原版实测 | 本项目 |
|---|---|---|
| 卡片 | 140 × 100，圆角 12px | `140u × 100u`，圆角 `12u` |
| 半径 | 450px（810–1199 档 400 / <810 档 330） | 同（三档都在） |
| 张数 / 步进 | 40 张，每张 `rotateY(9deg)` | 同 |
| 透视 | `perspective: 1200px`，origin 50% 50% | `1200u` |
| 底座俯角 | `rotateX(-7deg)` | 同 |
| 投影包围盒 | 1157 × 275（盒高 430） | 同比例（换算见下） |

**卡片定位三步，少一步都不是这个形态**：`rotateY(i·9°)` → `translateZ(R)` → **`rotateY(90deg)`**。

- 第三步是关键：卡面转 90° 后是**沿着切线**朝外，不是法线朝外。于是正对镜头那张是立起来的「刀刃」，画面正中间因此有一道缝；真正看清的是斜向两侧一路退开的卡面，形成左右两片扇形。
- **不要加 `backface-visibility: hidden`**：卡片切向朝向，环有一半永远背对镜头，两面都画出来才是原版那种「左右对称、左右互为镜像」的样子。实测一加就塌成半边，环还会偏到一侧。
- **四层，顺序不能换**：`.ring`（透视容器）→ `.ring-plane`（底座俯角，入场时从 -73° 立起来）→ `.ring-yaw`（光标视差 `--tilt` / `--yaw`，JS 每帧写）→ `.ring-wheel`（只有它在自转，卡片方位角是静态的）。

**尺寸只有一个真源**：`--h`（盒子高）⇒ `--u: calc(var(--h) / 430)` = 原版 1px @1440。内部所有尺寸都写成 `calc(n * var(--u))`，**连 `perspective` 也跟着缩** —— 否则环变小了透视还是 1200px，近处那张会突然变大、比例失真。

`--h` 的取值：桌面 `min(32vw, 100cqh)`，平板（810–1199）`min(39vw, 100cqh)`，手机 `<810` `min(48vw, 100cqh)`。系数不是拍脑袋：环的投影宽 ≈ 2.69 × 盒高，32vw 刚好让环占满约 **86% 视口宽**；窄屏半径降档后投影变窄（2R+卡宽 = 1040 / 940 / 800 u），所以系数跟着放大，三档都维持同样的 86%。

### 首屏版式（这次改过）

- **文字在上、环在下**：`.hero` 是纵向 flex 两段 —— `.hero-copy`（版心对齐导航，≥1024 分两栏：左标题 / 右正文+联系方式）＋ `.hero-stage`（`flex:1`，环在里面水平居中）。
- **`.hero` 必须写死 `height: 100svh`**，不能只写 `min-height`。不然 flex 子项是「不确定高度」，`.hero-stage` 上的 `container-type: size` 会把 `cqh` 解析成 **0**，整个环塌成 0 高（实测踩过，环直接消失）。
- **`overflow: clip` 而不是 `hidden`**：`hidden` 会让 `.hero` 变成滚动容器，整屏吸附（`FullPageSnap`）随即失灵。
- **`.hero` 不能再挂 `min-height` 下限**（旧版是 `640px`）。窗口比 640 矮时 hero 会撑出视口，
  环的下缘连同舞台裁切线一起被推到屏幕外 —— 矮窗口里「环底部被切掉一截」就是这么来的。
  现在 hero 恒等于 `100svh`，高度不够的部分交给 `.hero-stage` 的 `flex:1 1 0` 吸收（可以很小，但绝不出屏）；
  底部再留 `padding-bottom: clamp(.6rem,1.8svh,1.25rem)` 当呼吸位。
- **`.hero-stage` 用 `flex:1 1 0` + `min-height:0`**（旧版是 `auto` + `min-height:170px`）：
  820~1023 这个单栏区间文案最高，旧的最小高度会把舞台顶穿 hero 底部（实测 900×800 溢出 28px）。

### 三个必须记住的数

- **`translate: 0 calc((-58 - var(--lift)) * var(--u))` 只能加在 `.ring` 自己身上**：俯视时近侧被放大、远侧被缩小，投影的重心比环心低 58u（原版：盒心 450、带子重心 508）；`--lift` 是视差补偿（见下节）。平移透视盒 = 环和消失点一起走，投影不变；**平移 `.ring-wheel` 就会改变环心与消失点的相对位置，带子立刻被压扁（实测 295 → 233）**。
- **入场**：`ring-rise`（整圈 -73° → -7°）＋ 每张卡 `rotateX(-90deg)` 翻起来，按 `--i` 错峰 16ms。`@keyframes` 只写 `from` 帧 —— `to` 就是元素自身的 `transform`。
- **交互**：匀速 `-4°/s`（原版实测 2°/s 采样 ≈ 4°/s）+ 指针拖拽甩动（`DRAG = 0.4`，松手后惯性指数回落到匀速）+ 光标视差 ±6°（原版 Yaw / Tilt 也都约 ±6°）。`prefers-reduced-motion` 下只画一帧静态构图。

### 素材

`works/` 里**均匀抽 40 张**（间隔取样，覆盖 Logo / 活动 / 品牌 / 包装 / 排版 / IP 等各类目），预先裁成 **1.4:1（= 卡片比例）、640×457、webp q76**，放在根目录 `ring/`（单文件版用）与 `taste-design/public/ring/`（Next 版用），40 张合计约 1.1MB。

- 卡片内图片用 **fill**：`position:absolute; inset:0; width/height:100%; object-fit:cover`，不留白边、也不拉伸。
- 原图是 4001×2251 的整页稿，直接引会一次拉 37MB；`ring/` 里是缩略图。换素材时重跑一遍裁切即可，文件名保持原编号（`012.webp`），代码里只存编号。

### 环底部被「切平」的坑：视差 + `overflow:hidden`

最容易复现、也最难查的一个 bug：

- **现象**：第 1 屏的环最下面一排卡片被一条水平线齐刷刷切掉，切口下方是干净背景。
- **触发条件**：**光标停在窗口下半部**，别的什么都不用做。`--tilt` 由
  `(0.5 − clientY/innerHeight) × 12°` 驱动，光标在下半屏时 `tilt → −6°`，环的**近端**（画面下方那半圈）
  被压低 —— 实测 6° 时带子下端比盒子底边多出 **50~90px**。
- **为什么会被切**：`.ring` 当时是 `overflow:hidden`（照抄原版）。只按「光标不在环上」测，
  带子离盒子底还有 15~35px 余量，一切正常；一旦光标下移，余量立刻变负 → 被 `.ring` 的裁切盒子切平。
  这也是为什么之前 18 档视口回归全绿却仍然被用户看到 —— **回归脚本没动鼠标**。
- **修复三件套**（两个交付版都改了）：
  1. `.ring` 改 `overflow:visible`：卡片探出盒子也不再被切（横向本来就装得下，2.69×盒高 < 100vw）；
  2. 视觉上把环抬回去：JS 每帧写 `--lift = max(0,−tilt) × 9`（单位 u），
     `translate` 改成 `calc((-58 - var(--lift)) * var(--u))`。系数 9 而不是实测需要的 ~10：
     抬太多会顶到上方文案（600 高窗口只剩 ~1px 余量）；
  3. 盒子外再留余量：`.hero-stage` 和 `.hero` 各自有 `padding-bottom`，探出的部分落在这一段里。
- **回归方法**：`page.mouse.move(w/2, h-2)` 之后再量 `.ring-face` 的并集包围盒。
  全量 22 档宽度 × 14 档高度 × 3 个光标位置（中/顶/底）跑过一遍，无「出窗」、无 10px 以上的「压文案」。

### 矮窗口：`@media (max-height:720px)`

联系方式改成上下两行之后，第 1 屏文案高了约 70px。360×640 / 375×667 / 600~720 高的笔电上，`100svh` 装不下，
环会被 `.hero` 的 `overflow:clip` 切掉底部一截。所以补了一条**按高度**的断点（不是宽度）：
收 `padding-top`（`clamp(4.25rem,10svh,6rem)`）、标题字号、`.hero-rule` 上下距、`.hero-intro` 行高、
`.hero-meta` 的 `margin-top`/`gap`，并收紧 `.hero-stage` 的 `margin-top` / `padding-bottom`
（舞台不再有 `min-height` 下限，高度全由 flex 决定）。
再往下还有一条 `@media (max-height:620px)`（横屏手机 / 分屏笔记）：标题、正文、间距各再收一档，
保证下半区还能留出一百多像素给环。
**这条断点靠 `vh` 而不是 `vw`**：同样是 1440 宽，640 高和 900 高需要的是不同的间距。
⚠ `.hero-meta` 的间距**不能写进这一个块**：它的基础规则在文件里更靠后，同权重后写者胜，
写在一起会被反压回去（第一版就是这么写的，实测 `gap` 仍是 18.4px）。所以要单独补一条
`@media (max-height:720px){ .hero-meta {…} }` 放在 `.hero-meta` 基础规则之后 —— 两个交付版都是这么摆的。

## 五、首页第 2 屏：3D 卡片长卷（七类出品）

对位参考站 <https://intuitive-choice-476513.framer.app/> 的实际效果（Framer 的 3D Card Carousel）。

**★ 真实几何（用 Playwright 逐帧解 matrix3d 得到，第二版才搞对）：**
参考站是一排**恒定 `rotateY(90°)` 的鳍片**——像书立/墓碑一样全部侧对镜头，
沿 x 轴严格等距 160px 排开（= 0.42 卡宽），z 全为 0，双面贴图（front/back 各 ±4px 厚）。
两侧卡片「朝观察者张开」**不是卡片转了角度**，是**离轴透视**：透视 1500px、
原点压在卡片顶边（`720px 333px`），离屏心越远视线与鳍片夹角越大，
露出的画面越多——正中只剩 ~15px「书脊」，屏幕边缘露出 ~70% 画面（投影 262px）。
顶边因此保持水平、底边向后收——「海报墙向后倒」的透视感。

> ⚠️ **两版都做错过**（第一版圆柱、第二版「各转各的角度」）：
> ① 第一版做成了**圆柱轮播**（7 张绕大圆、整体旋转），半径一小只剩 3 张出屏；
> ② 第二版按「各转各的角度」做（`90° + x/视宽×92°`）——把投影宽度的变化
>   误读成了角度变化，人为压平了透视纵深，用户看一眼就说「效果不太对」。
>   **正确答案是最笨的那种：所有卡都转死 90°，一切交给透视。**

**这一屏没有黑色蒙版**：底色就是全站 shader，只在带子后面加一团蓝色辉光
（`.cards-stage::before`），这是光，不是压黑。

| 参数 | 参考站实测 | 本项目 | 说明 |

| 卡片姿态 | `rotateY(90°)` 恒定 | 同 | 别再加按位置的附加角度 |
| 间距 | 160px = 0.42 卡宽 | `--gap-k: .68` | 卡顶 24px 卡名要放得下；残余投影重叠由 z-index 精确排序兜底 |

> ⚠️ **间距为什么是 .68 而不是参考站的 .42**：参考站的卡片几乎**不重叠**——实测相邻卡
> 屏幕间隙是 3~142px，只有最外侧叠 8px。而 .46 时间距 132px、一屏塞 13 张，外侧卡的
> 投影宽 217px 远超间距，**边界互相压住 144px**。卡片是「绕自身竖轴转 90° 的刀片」，
> 相邻刀片在 z 向本就相交（卡深 = 卡宽 > 间距），屏幕投影再重叠时浏览器只能按元素中心
> 排序，于是**右半屏的层叠顺序就乱了**（谁压谁看运气）。
>
> ⚠️ **右半屏层叠顺序的真正根因（2026-10-18 深夜才挖到）**：`.band` 是平面合成
> （默认 `transform-style:flat`），**卡与卡根本不在同一个 3D 渲染上下文里**，浏览器只按
> **DOM 顺序**绘制。DOM 按 x 升序建 → 左半屏「先画外侧再画内侧」碰巧正确，右半屏
> 「先画内侧再画外侧」就反了（几何上离屏心越近的鳍片离视线越近，应该在上面）。
> 用 `elementFromPoint` 抽重叠区中点可以当场验证：左侧返回内侧卡、右侧返回外侧卡。
> **修法是每帧按 |x| 给卡片写 `z-index`**（离屏心越近值越大；悬停那张再 +1000 垫顶），
> 值互不相同 → 顺序永远确定，投影重叠多少都不再赌运气。之前用「把间距拉大到 .62
> 让投影不重叠」只是绕开问题，远端鳍片（视口边缘外）照样会叠、照样错。
>
> ⚠️ **卡宽为什么要跟 vw 挂钩**：用固定 `clamp(280px,21vw,420px)` 时，2560 宽屏的卡
> 被 420 卡住（只占 16vw，1440 时占 20vw），相对更小 ⇒ 一屏塞 11 张 ⇒ 离轴更远 ⇒
> 外侧投影膨胀回 −47px 重叠。改成 `min(40svh, max(240px,20vw))` 让「一屏几张卡」恒定，
> 2560 下卡宽 512、间隙 27~282px 全为正。
> 后来按要求连收两档：先 15%（`34svh / max(206px,17vw)`，1440 下 288 → 245），
> 再 20%（`27svh / max(165px,13.6vw)`，1440 下 245 → 196）。比例项不动，
> 间隙同比缩、仍全为正；层叠顺序由上面的 z-index 方案兜底，与间距解耦。

- **卡片定位只有一条公式**：`translate3d(x, 0, z) rotateY(90deg)`，`z` 平时为 0，
  悬停时浮到 90px。**没有按位置算的角度**。
- **卡是实体盒，20 面封出来的**（照参考站 sleeve-box 逆向：正面 `#161616` + 背面
  `#5c5c5c` + 4 条直边 + 每个角 4 段「弦」）：
  - `--ct` 板厚 `2.6% 卡宽`、`--cr` 圆角 `3.9% 卡宽`（参考站 8.39/380、15/380）、
    `--cl` 圆弧每段弦长 = `0.445 × --cr`。
  - 每条侧壁都是「宽 = 板厚、长 = 沿边」的窄条，靠 `rotateZ(φ) rotateY(90deg)` 立起来，
    法线 `(cosφ, sinφ)`；4 条直边 φ 取 0/180/±90，圆弧段 φ = ±θm 或 180±θm。
  - **圆角必须用弦去拼，只给 `border-radius` 不行**：近端截面的上、下角要顺着圆弧
    弯进卡面，才读得出「一块板」；做成方头直线时，侧对看就是一条描边。
  - 弦长放大 14% 让相邻段互相压住：等长共边会因抗锯齿在缝里漏出背景，看上去像
    一圈圈台阶。
  - 侧壁必须 `backface-visibility:hidden`：卡恒为 `rotateY(90°)`，只有**近端**那面墙
    法线朝向观察者，远端那面该被板身挡住。不剔除就两头各一条灰边，像加了相框。
    （几何上近端是「背离屏心」的那一侧：左侧的卡灰边在左，右侧的卡灰边在右。）
  - 截面渐变用参考站那组色标 `rgba(0,0,0,.22) → 透明 27% → rgba(255,255,255,.14) 75%
    → rgba(0,0,0,.16)`，沿**厚度**方向。别用 `#b3bbc9`（峰值 181）：太亮，看起来是
    一条白描边，卡还是两张纸。
- **卡片双面，两面都用素材图本身**（`.card3d-face.front` / `.back`）：屏心右侧的卡
  露出的是背面，所以背面必须也放图；两张都用 `card-3d/*.webp` 原图，**不自创卡背版面**。
  - **不要给背面的 img 加 `scaleX(-1)`**：卡片从 90° 翻到 180° 时，背板的法线由 −X
    转到 +Z，全程都是**正面**朝向观察者（实测在背板上注入不对称文字，90° 与 180°
    两个状态读起来都是正的）。再加镜像，悬停翻正后画面就左右反了。
  - 素材里出现的镜像 logo（如海报拼贴里的 `Gowin`）是**图片本身的设计**，不是渲染问题；
    判断朝向要看背板上叠加的文字，别被画面内容误导。
- **卡名拆出 3D**（`.cards-caps` 独立一层）：只跟位置不参与 3D，
  透明度按 `1 - d²×1.15` 衰减（d = 离中线距离 / 半屏）。
- **卡名挂在卡片上方、竖排小展签**：`top: calc(50% - ch/2 - 0.09cw)` + `translate:-50% -100%`。
  之所以不像放在下方那样要补偿 0.135 卡宽 —— 透视原点就压在卡片顶边（`50% − ch/2`），
  顶边的投影**不外扩**，留 0.09 卡宽呼吸带就够。
  字号定值 24px；因为 24px 的四字名 ≈96px 宽，编号若排同一行整条就是 ~130px，
  比 1024 档的卡位间距（`0.68×165≈112px`）还宽 —— 所以改成**编号在上（`.n`，14px mono）、
  名字在下（24px）**的两行展签，宽度收敛到 96px，1440→390 各档间距都放得下（实测 0 咬合）。
- **悬停判定按位置算，不靠 `e.target.closest()`**：正中那张是 15px 的书脊，
  指针根本停不上去。把指针 x 换算成卡位序号。
- **悬停效果 = 翻转**（参考站实测：被悬停那张从 90° 翻到 ~0°、前推 226px、放大 1.07）：
  卡片从侧对鳍片**转到正对观察者**——左半屏转到 `0°`（看正面）、右半屏转到 `180°`（看背面），
  两边都只转 90°，不会绕大半圈；同时向镜头推进 `0.52×卡宽` + 放大 6%。
  过渡是 190ms 时间常数（太快像硬切）。**两侧邻卡会被整体推开**给它腾位置：
  基础量 `0.40×卡宽`（实测 1440 下两侧各留 ~95px 空隙），且**左右不对称**——外侧邻卡离屏心远，
  离轴透视下露出的画面更宽（一侧能露出 100px+），所以 hover 卡越靠边外侧推得越远
  （`0.40 + 0.34×|hx|/卡宽`，最多到 ~0.74×卡宽）；内侧邻卡贴着屏心几乎不放大，
  恒定 `0.20×卡宽`。不做这个不对称补偿，就会「外侧压住邻卡、内侧空一大块」
  （参考站左推 263 / 右推 109 正是这个原因）。让位是「整段等量平移」不是逐个递增：
  相邻卡中心距始终 = `gap`，像拉链从 hover 卡两侧裂开，跨循环接缝也不会多出缝。
  方向按「环绕序号差」判左右。
  > 转 180° 那侧必须给 `.card3d-face.back img` 加 `scaleX(-1)`：背面本身已被转 180°，
  > 再镜像一次画面（尤其文字）才是正立的。
  > 卡名挂在卡上方，悬停时要**反向抬** `−0.075×卡宽`。抬的量不是按「卡高 ×1.06 × 透视」估的：
  > 卡片顶边在透视原点上方只有 `0.06×ch/2`（scale 差）× 透视 1.15 ≈ `0.052×卡宽`，
  > 所以 0.075×卡宽刚好留出呼吸；一开始按 0.19 给，卡名会明显「飞离」卡片。
- **静止会缓慢左移**（26px/s）：指针进舞台就暂停（否则 hover 目标一直跑），
  点击置中后停 2.6s，拖拽结束后停 1.8s。系统开了「减弱动效」时完全不流动。
- **拖拽手感**：`touch-action: pan-y`（竖滑翻屏、横滑拖带子），1:1 跟手，
  松手后按 `exp(-dt/300)` 衰减到 5px/s 以下归零。
- **点击置中也按位置算，不用 `e.target.closest('.card3d')`**：`pointerdown` 里
  `setPointerCapture` 之后，`pointerup` 的 target 会被改写成 band 本身，closest 永远
  取不到卡；而且卡上 `data-i` 存的是 `i%M`，索引空间和 `centerOn()` 差一截。
  用 `centerOn(idxAt(e.clientX))` 两件事一起解决。
  （正中那张的投影宽恰为 **0**：它压在透视原点的 x 上，90° 鳍片的所有点都投影到同一条
  竖线上 —— 这是几何正确，不是 bug。）
- **循环**：三份 7 张 = 21 张，`shift` 折进 `[-span, span]` 里取模，
  两端卡片在屏幕外完成跳变，看不出接缝。
- **窄屏**（`≤700px`）：卡宽 `min(26svh, 42vw)`、间距 `.62`，390 屏 4~5 张鳍片。
  窄屏把卡名里的编号 `.n` 隐藏：24px 的四字名 ≈96px，卡位间距 `0.62×164≈102px`
  刚好放下名字一行，再带编号（竖排 +30px 高）整块展签会顶到页头。

> 两个交付版同构：单文件版在 `<script>` 第 5 块（21 张卡由 JS 建 DOM），
> Next 版是 `src/components/CardCarousel.tsx`（卡片由 `WORK_DECKS` 渲染，JS 只读节点）。
> 文案与素材一一对应：`card_logo / card_brand / card_events / card_package /
> card_layout / card_ip / card_other`。

### 5.1 作品集模式（点击卡片后，单文件版当前实现）

- **进入 / 退出**：点击任意一张卡 → 整条长卷**连贯地**收起成顶部一排 7 张「门类筛选器」；
  `.cards-screen` 挂 `is-works`，`--cw` 收到 `clamp(24px,6.2vw,88px)`，`cards-head` 隐藏，
  舞台收成一行。收拢过渡 720ms（缓出）：中间 7 张从大卷位置 / 90° 插值到固定位置 / -15°，
  **14 张循环副本同步淡出并向屏心收拢**（不是瞬间消失）。此后点击某张卡 = 切换下方作品
  的一级分类（`ITEMS[].s` ↔ 作品目录 `D.S[].s`，经 `window.__WD.enter(slug)`）。
  **滚轮向上（deltaY<0）/ 左滑到最左 = 退出**：缩小组**不散开**，整块原样往下沉 + 渐隐
  （`.is-leaving-works`，opacity .26s / 位移 .3s），300ms 后 `finishWorksExit()` 撤
  `is-works`、换回大卷布局并 `mountBack()`，舞台再从 `opacity:0` 淡回，之后可再次点击进入。
- **⚠ 退出必须恢复大卷尺寸（修「回大卷后排列错乱」）**：`is-works` 会把 `--cw` 换成
  缩小组卡宽，`enterWorks` 随后的 `measure()` 把 JS 里的 `cw/gap/span` 全覆盖成小值；
  撤掉 `is-works` 之后 **必须再 `measure()`**，否则 `gap` 残留小值、21 张卡按
  小间距挤成一团。
- **⚠ 退场只动整块舞台，单卡排列一帧不改（用户要求「不要改变排列」）**：
  `.is-leaving-works` 只给 `.cards-stage` 写 `translateY(2.6vw+42px)` + `opacity:0`；
  render 在 `exiting` 期间依旧按缩小组终态写每张卡的 transform，并且 `tick()` 冻结
  `hov[] / selHov[]`、`pointermove / pointerleave / click` 直接 return —— 否则悬停中的
  那张会在淡出的 260ms 里自己缩回去、邻卡跟着让位，看起来就是「排列被重排了一遍」。
- **⚠ 换回大卷时 `els[i].style.opacity` 必须显式写 `'1'`**：缩小组把 14 张循环副本的
  opacity 写成 0，大卷分支的 `if(e<1)` 在入场结束后不再写 opacity，不显式复位的话
  那 14 张会一直隐身（长卷只剩中间 7 张）。旧版是靠退出散开动画里的
  `opacity=exE` 兜回来的，散开动画删掉后必须补这一笔。
- **卡片的统一朝向**：`rotateY(-15°)` 恒定 —— **hover / 激活都不改角度**（用户实测反馈
  「每一个朝向都有点差别」，根因就是 hover 翻到 0°；现在 hover 只浮起 `0.5cw` + 放大
  1.05，激活卡浮起 `0.12cw`，两侧邻卡让位 `0.2cw`，让位方向按序号差、不 wrap）。
- **⚠ 间距不能复用大卷的 `--gap-k`（0.68cw）**：那是给 90° 鳍片设计的（投影极窄）；
  -15° 近正面卡的投影宽 ≈ 卡宽。worksMode 间距系数读 CSS 变量 `--ws-gap-k`
  （桌面 1.5 分散 / ≤1023.98px 收 1.26，390 屏整排 ≈352px 刚好放下）——
  render 与 `idxAt` 都读同一变量，改 CSS 即可。
- **作品集布局（左右 + 横向图片流）**：`.cards-works` 左右排布 —— 三级列表
  （左栏竖排，宽度收窄为 `clamp(120px,13vw,190px)`）在左、图片流在右。
  **图片流纯横向**：每个 `.wd-work` 是「标题在上（横排）+ 图片组在下」的纵向单元，
  图片组 `.wd-imgs` 内多张图片**横向一字排开**（无上下堆叠）；图片高度跟随显示区域、
  宽度按宽高比撑大。作品页脚本
  measure / sync / jump / enter / shade 经 `window.__worksMode` 切纵横轴；
  三级列表纵向归位（`reveal()` 里 L3 走 scrollTop）。
- **⚠ 图片高度用明确 CSS 变量 `--ws-img-h`（修「图片与三级菜单对不上」）**：
  图片 `height:var(--ws-img-h,52svh)` + 内联 `aspect-ratio`，高度值由
  `syncImgH()` 在 `moveWorksIn()` 后量 `.wd-feed` 实际高度写入（rAF 延迟一帧）。
  不能用 `height:100%` 或 `auto`：懒加载图片未加载时无固有高度，百分比链
  （.wd-feed→.wd-feed-in→.wd-work→.wd-imgs）首次 reflow 没排稳 ⇒ 高度算 0 ⇒
  aspect-ratio 算不出宽度 ⇒ 远距离作品的 `offsetLeft` 全错、`enter` 定位错位。
  明确高度 + aspect-ratio ⇒ 图片无论是否加载都立即占住正确宽度。
- **去掉顶部模糊 + 黑渐变**：`.cards-works .wd-lq{display:none}`（图片流顶部
  6 层 backdrop-filter 模糊整条隐掉）、`.wd-lq-tint` / `.cards-works::after`
  黑色渐变也 `display:none`。
- **去掉上下黑渐变**：`.cards-works .wd-lq-tint{display:none}`（顶部黑渐变）与
  `.cards-works::after{display:none}`（底部黑渐变）都隐掉；6 层 backdrop-filter 模糊
  仍由 `.is-scrolled` 控制（滚动后才出现，顶部黑幕不再有）。
  （后续更新：顶部 6 层模糊也一并隐掉，见上「去掉顶部模糊 + 黑渐变」。）
- **退出淡出（修「返回动画卡顿」）**：退出作品集时 `.cards-works` 加 `.is-fading`
  （`opacity 0`、`.28s` 过渡）—— 与缩小组下沉同时进行，作品集（三级列表 + 图片流 +
  6 层 backdrop-filter）快速淡出，卸掉每帧重算模糊的渲染压力；`finishWorksExit` 里
  `mountBack()` 之后移除 `.is-fading`（`enterWorks` 里也会移除，防残留）。
- **滚轮驱动**：`.cards-screen` 上的 wheel 监听（passive:false）—— worksMode 下
  `preventDefault` 掉页面吸附滚动，`deltaY>0` → `feed.scrollLeft+=deltaY`
  （内容从右往左看）；`deltaY<0` → 直接退出回大卷。
- **三级 chips 在作品集模式下按「一级」过滤**（显示该类全部作品，如包装 12 项）——
  作品集里没有二级导航，仍按「一级+二级」过滤的话每组只剩 1~3 项、其余作品没有入口。
  二级页（无 `__worksMode`）保持原过滤。
- **⚠ 菜单点击委托必须挂 `document`**：原绑在 `#page-detail` 上，作品集模式下
  `.wd-list` 移进第 2 屏后点击不再冒泡经过 page-detail，chips 点了没反应（实测）。
  现按按钮类名 `wd-(l1b|l2b|l3b)` 判定，二级页行为不变。
- **作品集 DOM 是「移动」不是复制**：`#page-detail` 里的 `.wd-list` + `.wd-feed-wrap`
  由 `moveWorksIn()` `appendChild` 进第 2 屏的 `#cardsWorks` —— 作品页脚本持有的
  getElementById 引用不变，数据 / 滚动状态不丢。退出作品集时 `mountBack()`
  把它们移回 `.wd-in`；第 2 屏在作品集展开状态下点导航去别的屏，`__WS.leave()`
  也会走同一条退场路径。
  **`page.hidden` 的判定相应改成 `pageHidden()`**（= `page.hidden && !window.__worksMode`）：
  作品集在第 2 屏展开时 `#page-detail` 仍是 hidden，按旧判定 measure/reveal 会被整个跳过。
- **`#page-detail` 现在只是「常驻 hidden 的数据宿主」**：`#/works` 那张独立页
  （标题 + Deckshift 牌堆、`.works-page` / `.deck-*` 样式、`DECKS` 数据、路由里的
  `works → detail` 分支）已整体删除，这份三栏 DOM 只服务于第 2 屏的作品集。
- ⚠️ **`.card3d` 必须显式 `transition:none`**：reduce 下全局
  `transition-duration:.01ms !important` 会把过渡激活 —— 尺寸一变，同步读
  `offsetWidth` 拿到的是**过渡起点**的旧值（实测 196 ≠ 88），worksMode 的
  `measure()` 就用错间距（两侧卡散出屏幕）。`transition-property:none` 让
  `!important` 的 duration 无的放矢。
- 窄屏（≤700px）卡名整个隐藏（卡位间距太窄放不下四字名），当前分类靠激活卡
  的浮起指示；`reveal()` 在作品集模式下对三级 chips 行始终做横向归位（桌面也执行）。

## 六、末屏：泡泡池（Bubble Pit）

原「第 3 屏：3D 品牌球」（`#about`，84 张卡按 Fibonacci 排布在球面上）**整屏删除**，
14 个合作品牌改成末屏的「泡泡池」，参考 <https://bubble-pit.framer.website/>：
透明背景上，一群印着 logo 的玻璃球**从窗口顶部落下**，砸到底部堆成一层；
指针扫过把球推开，按住一颗可以抓起来再甩出去。**球层铺满整屏、压在文案之上** ——
球下落时会从标题、邮箱、联系信息前面扫过去。

### 6.1 版式与层序

- 末屏 `#contact` 仍是 `min-height:100svh` + `flex-direction:column`：上半是原来的
  三段式文案 + 联系信息（`.wrap`），下半「泡泡池」不再是 flex 子项而是整屏覆盖层。
  **底色已按用户要求改为透明**（v32，原来是 `#000`）：露出底下那层 WebGL 棱镜光带。
  ⚠ 代价与补偿：亮光带流动时会扫过文案和球堆 —— 白字压在亮带上对比度不足（右下角
  「中国 · 深圳」这种小字最吃亏），球缘在亮处也会融进背景。文字侧用 `.contact`
  上的一层轻 `text-shadow` 兜底（不加任何背景暗层，保持「无黑底」的观感）；球侧靠
  `.pit::before` 的冷光 + 球体自带的内描边撑住。若日后光带参数变动导致球糊，
  优先调低 shader 亮度或给球加描边，**不要又把整屏底色改回纯黑**（用户明确要去掉）。
- **层序**：`.pit` 是 `position:absolute; inset:0; z-index:3`，`.wrap` 是 `z-index:2` ——
  这就是「文字在球的下面、球在前面」。球从 y≈-R 一路落到屏底，全程都压在文字上。
- ⚠ **球层必须 `pointer-events:none`**。它铺满整屏，若接收指针事件，底下的 mailto、
  电话、微信那几行链接就再也点不到了。拖拽与悬停改在 `.contact` 上监听（见 6.4），
  只有真正命中球时才 `preventDefault`。
- 顶边 `mask-image:linear-gradient(to bottom,transparent 0,#000 min(3.4%,34px))`：
  球是从画布上方掉进来的，画布边界会硬切一道；只糊 34px，够让球「从黑里探进来」，
  又不会把刚进画面的球整颗糊掉。
- `.pit::before` 是贴底的冷光（蓝 `rgba(30,84,196,.24)` + 一点紫 `rgba(78,48,158,.11)`，
  跟球的新配色同族），把深色球从近黑底里托出来。
- 窄屏（≤760）竖向节奏整体收紧一档（`padding-top` / 标题 / `lede` / `mailto` / `rule` / `footer`），
  meta 行距也收一档；再矮一档（≤840 高，360×800 与 375×812 这类）`rule` 与 meta 行距
  各再收 8px。球层是覆盖层、不占布局，所以文案再高也不会把球挤出视口 ——
  代价是球堆会压到文案上：390×844 下 2 层（148px 堆高）堆顶球缘 698、文案底 642，
  余 56px；360×800 只剩 158px 的「文案底 → 屏底」，正好等于堆高，所以那一档必须
  把文案底压到 626（余 18~28px）。窄屏因此必须锁 2 层，见 6.3。
- **文案整体往下压了一档**：`padding-top` 从 `8svh`（900 高时 72px）提到 `14svh`
  （900 高时 126px）。原来「Say Hello」几乎贴着导航，整块文案像被顶在画面之上。
  ⚠ 上限是被球堆卡出来的：再往下压就开始盖住「微信 / 电话」那一行（球在前、字在后，
  是真盖住）。移动端 `padding-top:5.25rem`（导航在 390 下高 80px，原来的 3rem 会让
  小标题压在导航底下）。
- **矮屏（≤720 高，iPhone SE 这类）单开一档**：单列 meta 自己就 240px，文案整块
  505px + 球堆 194px 塞不进 667 的视口，meta 会被球压掉一半。这一档让 meta 转两列、
  标题与各段间距再收一档，全部落到球堆顶边之上。

### 6.2 球面：三层预渲染，logo 可以任意倾角

球面不是一张位图，而是**球体 / logo / 高光三层**，绘制顺序 `球体 → logo(按倾角旋转) → 高光`：

| 层 | 缓存 key | 画什么 |
|---|---|---|
| `ballSprite(tone)` | 色调（4 张） | 径向渐变底色 + 底部冷光 + 贴球缘内描边 |
| `markSprite(brand,ink)` | 品牌 × 是否反色（≤ 球数） | 只有 logo 本身，透明底 |
| `hiSprite(tone)` | 色调（4 张） | 左上椭圆光斑（裁进球内） |

⚠ **必须拆开的理由**：logo 要按各自的倾角转（见下），但高光不能跟着转 —— 光源永远在
左上，高光一转球就「翻」了。烘成一张位图就只能整颗转，那正是旧版 logo 全部水平的原因。
拆开之后球体只剩 4 张可复用（原来按 `品牌+色调` 要 15~31 张），1440 下总共
`4 + 15 + 4 = 23` 张位图，比原来更省。

**logo 倾角**：全水平排开像一页印刷品。每颗球带一个 `ang`：

- 起始 `ang = ±34°`，另有约 **1/5 的球直接甩到 ±70°** —— 只给小角度还是「一排稍微歪的
  印字」，偶尔几颗歪得狠的，一池球才活。任意角度都转不出球外（logo 半对角只有 0.39R）。
- 球的移动带着 logo 滚：`ang += vx / r * dt * 0.7`（0.7 是视觉系数；按 1.0 转，被甩出去的
  球会像风车一样飞）。纯视觉量、不参与碰撞 —— 等质量圆没有旋转惯量。
- 抓着球横向拖也要滚：`ang += (位移 / r) * 0.8`，否则手里那颗像被图钉钉在屏幕上。
- 实测静止后倾角跨度 68°~156°，接近水平（<6°）的只有 1~3 颗（见 6.6 的表）。

球体本身（`ballSprite`）的组成：

1. 径向渐变底色（光源统一左上）→ 四套色调：
   | tone | 用途 | 底色（亮→暗） | logo |
   |---|---|---|---|
   | `dark` | 近黑玻璃 | `#4a4e57 → #06070a` | 白 |
   | `ivory` | 象牙瓷 | `#ffffff → #c6c0b2` | 深灰 `#15171b` |
   | `blue` | 蓝玻璃 | `#a2d0ff → #071029` | 白 |
   | `purple` | 紫玻璃 | `#c9adff → #140931` | 白 |
2. 底部冷光（每套色调自带颜色，蓝紫球的冷光更亮）；
3. 内描边（贴球缘一圈亮边）。线宽 `1.6px × √(R/45)`：固定 1.6px 放到 90px 的球上会细成
   一根发丝，整颗球反而显得「塑料」。

- **每颗球按自己的 `b.r` 画**（不是统一 `R`）：物理半径本来就带 `0.94~1.0` 的差，
  视觉跟着走，球堆才咬得紧、也才有大小差。
- **配色随机、不再交替**：原来是「深色 / 象牙」严格交替，一池球看下来像排好序的棋子。
  现在按权重抽 `dark .34 / ivory .28 / blue .21 / purple .17`，并**强制同一品牌的两颗球换色**
  （14 个品牌在一屏里会各出现 1~3 次，纯随机会连出两颗一模一样的球）。
- ⚠ **球少了之后权重抽会缺色**：球放大一倍、一屏只剩 16 颗时，「一颗紫都没有」的概率约 5%
  （实测撞到过）。所以前 8 颗先按「四色各两颗」的洗牌**配额**发，后面再走权重随机 ——
  再小的池子也保证蓝、紫各至少两颗。实测 1440 是 5/4/3/3、390 是 3/3/3/2。
- ⚠ **白 logo 放到浅色球上要染色**：`source-in` 只保留非透明像素再灌 `#15171b`，
  等于给 logo 做了一次实心蒙版。`BOX` 里存的 alpha 包围盒比例必须先裁一刀 ——
  14 张图都是 1000×1000，logo 只占中间一块，边距差 3 倍（`hansen` 只占 12% 高、`chao` 占 55%），
  不裁直接画会忽大忽小还偏心。裁完统一缩进「宽 ≤62% 球径、高 ≤46% 球径」的框。
- 素材直接 `<img>` 引用 `partners/*.webp`，**不内联 base64**；换图按同名替换即可。
- ⚠ **`imgs[brand] = im` 忘了写**过一次：球画出来了但一个 logo 都没有 ——
  `mount()` 只看 `loaded` 计数，`markSprite` 查 `imgs` 拿到 `undefined` 就静默 return。

### 6.3 物理：等质量圆 + 弹性，自己写

只需要「下落 / 堆叠 / 抛掷」三件事，通用刚体引擎反而难调稳（旋转惯量、接触流形都不需要）：

- 固定步长 `1/120`；单帧最多补 **80ms / 10 个子步**（切回标签页不会补一大段物理，
  但也不能把真实时间丢太多 —— 上限给 50ms 时，13fps 的机器上一场球雨要跑两倍长）；
- 每个子步 **4 次碰撞迭代**：只迭代 1 次的球堆会像液体一样互相挤压、永远停不下来；
- 位置修正 `FIX=0.50`（按质量分摊）+ 法向冲量（`REST=0.34`）+ 切向摩擦 `0.14`；
- **终端速度 `VMAX=1900`**：整屏球雨在 1440 高的屏上落差 1600px，不封顶能砸到 2700px/s，
  落进堆里把整堆掀起来、要七八秒才安静。
- 池底 `vy<24` 直接归零，横磨 `0.995/步`。
  ⚠ **千万别给 0.92/步**（≈每秒归零）：球会被粘在地上，指针扫过去推不动、甩出去的球也立刻刹住。
- **接触阻尼**：只对「这一帧真的碰到了东西」的球生效 —— 位置修正每次都会把
  重叠的球推开一点点，堆得越厚残速越大，球多的视口整堆会一直「低烧」在 100px/s
  上下，永远到不了静止判据。判据 `<110px/s 时 ×0.80/步`，且**跳过被指针推着的球**
  （不跳过的话推挤会立刻被吃掉）。没有接触的球（下落的、被甩到空中的）一律不动。
- **静止判定**：整堆 `|vx|+|vy| < 130` 持续 70 帧就 `cancelAnimationFrame`。
  ⚠ 入场没走完不许判静止（`t < maxDelay+0.25` 时清计数）：起初只有几颗球在落、其余还等着
  `delay`，「平均速度小」会被误判成静止 —— 一停 rAF，球雨就断在半空。
  ⚠ 阈值不能给 70：0.3px/帧的微抖肉眼不可见但永远不为 0，堆越厚抖得越大（2560 实测 ~100），
  门槛太紧的后果是永远睡不着。
  ⚠ **画布上方还有球时也不许睡**：两颗球挤在一起往下沉时，接触阻尼会把速度压到
  80px/s 上下（低于阈值），整场会被误判「稳了」、rAF 一停，球就永远悬在屏外
  —— 实测 2560 上出现过两颗停在 y≈-320 再也不下来。判据里加 `b.y+b.r<0` 计数即可。
- **离屏停表**：IntersectionObserver 观察 `.pit`，离屏 `stop()`。

#### 弹性：0.34 起步、0.62 只给快球

对照原站（bubble-pit.framer.website）逐像素采样后，发现原站的池子**从不真正静止**
—— 静置时每 700ms 仍有 8~12% 的像素在变，球堆像一锅文火粥。我们一度也做成了这样
（「沸腾」：堆稳后每 0.28~0.60s 从底层顶一颗球 + 软天花板兜底 + rAF 常驻），
但后来按用户要求**完全关掉了沸腾**，池子落定后真正静止、rAF 停表。高速弹性则保留：

- **慢速接触仍是 `REST=0.34`**：堆里的微抖、正常碰撞都走这条 —— 堆形稳、不低烧；
- **高速对撞（settled 且 |vn|>220）用 `REST_HOT=0.62`**：用户抛出去的球砸进堆里
  会弹开、掀翻邻球（原站的「球是活的」就来自这）。入场时 `settled=false`，球雨
  落地照样走 0.34，v23 的堆形失控不会复现。

**`settled` 的语义（关掉沸腾后）**：球堆第一次稳住（连续 55 步 `maxV<130`）时翻成
`true`，之后**永久保持**——它现在只做「高速弹性已就绪」的标记。球堆随后正常
`stop()`（`sleep>70` 停 rAF），但用户再甩球时 `wake()` 唤醒、`settled` 已经是
`true`，高速弹性照常生效。⚠ 关沸腾时不能简单把 `stop()` 的 `!settled` 去掉就完事：
高速弹性依赖 `settled`，而 `settled` 依赖 `sleep` 累计、`sleep` 依赖 rAF 在跑——
若 rAF 在堆稳前就停，`settled` 永远翻不到 true，甩球就砸不出弹性了。所以 `settled`
的翻转保留在 `sleep>55` 处，只删掉「沸腾冲量」和「常驻 rAF」两段。

（沸腾版的完整做法见历史提交：`boilT` 定时器、`b.free` 免阻尼标记、软天花板
`ceilY`/`THROW_CEIL_V`、`b.wx` 自转、冲量按球数缩放 `bScale`。重新引入时务必同时
盯着 `topY` 与 `hits()`。）

验证判据同步改回：`9s: rAF 已停`、新增「静止无自弹（1.5s 0 颗动）」、两条「重新
睡着」恢复（指针离开 / 抛球落回后 `running=false`）。

### 6.4 交互

- 事件挂在 `.contact` 上（球层是 `pointer-events:none`），坐标仍按 canvas 的
  `getBoundingClientRect()` 换算。
- **指针推挤**：以指针为圆心 `1.9R` 内把球往外推，加速度 `9000 × PF`（≈3.8×重力）。
  ⚠ 给 2600（≈重力）时密堆里只有 3 颗球受力、位移 0 像素；7000 才推得出一条路径；
  球堆变成实心两层砖缝后又加了 9000（1024 实测位移只有 11px，≈0.17R，看不出被拨开）。
  **`PF` 随球径放大**（`clamp(1, R/45, 1.8)`）：推力给的是「速度增量」，球大一倍后同样的
  增量只值 0.14R 的位移。
  朝下的分量再乘 0.3 —— 指针下方的球本来就被池底顶着，往下推等于白推。
  实测扫过 5R 的距离（扫球堆**上层**，见 6.6）：1440 推开 6/15 颗、最大位移 163px；
  1024 是 11/15 颗 / 66px；2560 是 20/32 颗 / 147px。
- **抓取抛掷**：`pointerdown` 命中 `1.12R` 内最近的球 → `setPointerCapture`，球跟着指针走；
  松手按指针速度 ×1.35 抛出（上限 2800px/s）。实测能把球甩到 y≈180（屏中部）再落回。
- ⚠ **抓完球要吞掉这一次 click**：松手后浏览器会把 click 派给球底下那个 `<a>` 上，直接跳走。
  抓过球就在 400ms 内用 capture 阶段 `preventDefault + stopPropagation` 吞一次。
- 光标：命中球时给 `.contact` 写内联 `cursor:grab` / 拖拽中 `grabbing`，`pointerleave` 清空
  —— 球层不能自己收指针事件，`cursor` 只能写在 section 上。
- ⚠ **`start()` 必须判 `inView`**：球层铺满整屏，滚走时指针会「离开」section ⇒ 触发
  `pointerleave` ⇒ `wake()` ⇒ `start()`。不挡的话 rAF 会在离屏后重新点亮，而 IO 已经不再
  回调（状态没变），于是永远跑下去、纯烧 CPU。
- 滚轮不拦截：球层上的滚轮照常触发「整屏翻页」，PageUp / PageDown 也一样。

### 6.5 四个必须记住的坑

- ⚠ **canvas 必须绝对定位**。canvas 有 `width/height` 属性（位图尺寸），一旦参与布局，
  `height:100%` 解析不出确定值就会退回「属性高度 ÷ dpr」当内在高度，反过来把父级撑大
  —— 实测 1440 下曾把池子从 360 顶到 720，整屏被顶出视口。
- ⚠ **球径只由宽度定**：`R = clamp(30, W/16×0.75, 84)`（基准 `clamp(40, W/16, 112)`
  整体缩小 75%，见下）。球层已经是整屏，`H/6.6` 那种「按高度定球径」的约束失去
  意义。⚠ 下限 30 已低于 logo 可读线（原 40 是 1000px 画稿缩进球里不糊的底线），
  窄屏 logo 会偏糊 —— 用户要求缩 75%，此代价待确认。
- ⚠ **球数必须跟着球径重算**：球缩小后同样宽度能放更多列，`perRow = floor(W/2R)`，
  行数**统一锁 2 行**（见下一条）：1440 / 1024 是 10+9=19 颗，2560 是 15+14=29 颗，
  窄屏（<520px）是 6+5=11 颗。
- ⚠ **行数从「按屏高 40% 反算」改成了「统一锁 2 行」**：球缩小 75% 后，原来的
  `rows = round(H/(R*2)*0.40)` 会在桌面端把行数从 2 行推到 3 行（球变小、同样屏高
  按公式能装更多行），球数翻倍、三行堆顶压到文案（1440 / 1024 实测压文案 1 颗）。
  锁 2 行后球堆是贴底的两层球毯、缝更大、堆更矮，压文案归零。2560 原来 3 行是
  「大屏铺满」的刻意设计，但球缩小后两行已铺满整宽，3 行反而过高。
- ⚠ **别用「按可用高度收缩球径」来救窄屏**（历史坑，球径已缩小时尤其注意）：
  球一小 `perRow` 就跨档，格宽只比球宽多一点点、上排球卡不进凹处、堆高反而涨。
  正确做法是动 CSS，或锁行数。
- ⚠ **落点要铺成「砖缝」，不要让每层共用同一套格点**：偶数层 `perRow` 格，
  奇数层 `perRow-1` 格、球心正好落在下层两颗相切的凹处（`slotW=(W-2R)/(perRow-1)`，
  首尾球心落在 `R` 与 `W-R`）。所有层共用一套格点时，上层球会顶在下层球的正上方、
  随时能再摞出第三层 —— 实测 1024 上有一列摞了 3 颗，堆顶被顶到 y=410，把
  「邮件 / 微信」那行盖掉了。错半格之后层数锁死在 `rows` 层，堆高可预期。
- ⚠ **球径只许比槽窄，不许比槽宽**：`scale = 0.94 + rand*0.06`。
  一颗比槽宽的球会把整层顶起来，堆高立刻失控。
- ⚠ **分层入场，不要一次全放**：上层球额外加 `+0.30s`（层间隔）。各层同时落时，
  上层总会有球正好压在下层球的头顶、平衡住不掉，堆顶高度在 447~566 之间乱跳
  （同一份代码连跑四次四个结果）；等下层落定再落上层，每颗都从凹处进屋。
  ⚠ 反过来把层间隔拉大到 0.90s 更差：上层球落定时下层已经堆好，全砸在堆顶。
  **0.30 这个「差一点、但还没落定」的间隔是对的。**
- ⚠ **掉落方向 = 从中间倾倒**（v31 改版，替代 v30 的左→右扫掠）：
  `delay = radial*SWEEP + 层号*0.30 + rand*0.05`，其中 `radial = |nx-0.5|×2` 是槽位
  离画面中心的归一化横向距离（0=正中间，1=最左/最右）、`SWEEP=0.25s` —— 中间先落、
  两侧对称地晚一点，像从中心漏斗往下倒。原版「槽位洗牌 + 落球顺序打乱」已删除，
  槽位按 x 排序取自然序。
  ⚠ **`SWEEP` 不能放大**：0.9 / 0.55 都试过，两端球拖到最后才落，此时中间堆已经
  压实、边界凹处被挤变形，晚落的上层球挤不进凹处、骑上堆顶压到两侧文案
  （© 2026 / 中国·深圳，实测约 1/4~1/2 概率、最深 47px）。收到 0.25 后「中间先动、
  两侧稍晚」的轻微先后波仍在，但所有球在堆压实前就全落地、凹处完好，压文案归零。
- ⚠ **上层球横向抖动锁 0**（v31）：中间倾倒后两端球都最后落，上层球一旦抖出凹处
  就被「墙 + 下层球」楔住、骑上堆顶（实测 x=110/1300 处压 10~47px）。上层锁死 +
  球径自带 0.94~1.0 的 6% 差异，落点仍有自然错位。下层仍抖 ±0.30 槽宽（见下）。
- ⚠ **弹性与堆形是一对矛盾**（详见 6.3）：`REST` 一抬，球雨落地就会「弹上去」，
  底排被撞散、堆顶在 447~660 之间乱跳并压住版权行。这一版把 `REST` 留在 0.34 ——
  要动它，先看 `topY`、`resting` 两个数，再跑一次 `__PIT.hits()`。
- ⚠ **切向摩擦别超过 0.20**：弹性高的版本里 0.30 会让球「粘」在堆顶斜面上、堆顶被
  架高 80px；0.34 恢复系数下 0.14 就够（落位不漂、斜面站不住）。
- ⚠ **球雨的 `delay` 要按球数自适应**：写死 `k*0.014`，球只剩 12 颗时整场只铺 0.23s，
  看起来是一波同时落地。现在每层铺 `0.16s`。
- ⚠ ~~**生成顺序要打乱**~~（v30 已反转）：旧版按列递增生成会「一列一列往下倒」像发牌，
  所以槽位与落球顺序都洗成随机；改成「中间倾倒」后**不再洗牌**，槽位按 x 排序、
  落球取自然序（见上）。

## 七、第 1 / 3 屏：联系方式 meta 的「正文」悬浮放大

- **鼠标悬浮到正文（`dd`）上放大 1.5 倍**：`transform: scale(1.5)` + `transition: transform var(--wd-pop)`，与作品索引页选中项同一套时长 / 缓动。第 1 屏 `.hero-meta` 与末屏 `.meta` / `#contact dd` 共用这套参数。
- **`transform-origin: left center`**：文字左缘（与 `dt` 标签对齐的那条竖线）保持不动，向右长出去；缩放不参与布局，后面的行 / 列不会被推开。
- **`width: fit-content` 是必须的**：`dd` 是块级元素、默认占满整行 —— 1920 下文字只占约半列，不收窄的话鼠标划过列内空白也会触发放大。收成文字宽之后，悬浮热区才等于文字本身。
- **第 1 屏是「标签在上、值在下」的上下两行**：中文标签（邮箱 / 电话 / 微信）加长邮箱如果并排，值会被挤到很窄的一格里。改成 `grid-template-columns:1fr` 之后值拿到整栏宽度，`×1.5` 永远撞不到标签或邻栏；行内 `gap:.28rem`、项间 `gap:1.15rem`（19.2px 放大后上下各溢 5.7px，实测只擦到标签盒底 1.2px，字面不重合）。
- **标签字号统一 12px**：`.meta dt`（第 1 屏与末屏共用）从 `0.7rem`（11.2px）改成 `12px`；Next 版末屏那几处 `text-[0.7rem]` 同步改成 `text-[12px]`。`letter-spacing:.2em` 保持不变。
  > `.hero-meta` 排在 `.meta` 之后：两者同权重（都是单类），靠书写顺序压过 `<640` 那条 `repeat(3,1fr)`。搬动这段时注意别把它移到 `.meta` 前面去。
  > Next 版这一屏是 Tailwind 工具类写的、没有 `.meta` 类名，所以 `globals.css` 里用 `#contact dd` 反查同一套规则。
- ⚠️ **收窄到 1100px 以下时，末屏放大后的正文会压到邻列文字**：最长的正文是 `hello@tastedesign.studio`（15.2px 下 178px），×1.5 = 267px，而这一区间的列宽只有 170 ~ 235px。广视口没问题（1920 / 1440 / 390 下净距还有 145 / 85 / 88px）。
  > **第 1 屏不受影响**：上下排版后值独占一行 —— ≥1024 时在右栏（1440 下 599px），<1024 时是整行宽（390 下 358px）；邮箱放大后 234px，余量充足。
  > 两个交付版的断点本来就不一样，所以受影响范围也不同：**单文件版**这一屏是「<640 一列 / 640~1023 三列 / ≥1024 四列」⇒ 640 ~ 1100 都重叠（1024 下 −19px、760 下 −24px、640 下 −57px）；**Next 版**用的是 `sm:grid-cols-2 lg:grid-cols-4` ⇒ <1024 是 2 列反而放得下，只有 1024 ~ 1100 这段 4 列区间重叠（1024 下 −19px）。
  > 要消掉就在 `max-width: 1100px` 以下收一档（与作品索引页窄屏同样收到的 1.15；640 下需要 ≤1.18 才干净）。

## 八、顶部导航的两态：常规 50% / 激活 100%

「首页 / 作品 / 关于我们」三项只有两种状态，全部由 `aria-current="page"` 一个信号驱动：

| 状态 | 判据 | 整项透明度 |
|---|---|---|
| 激活 | 当前所在屏（带 `aria-current="page"`） | **100%** |
| 常规 | 其余 | **50%** |
| hover（常规项） | 指针悬停 | 75%（中间档） |
| 键盘焦点 | `:focus-visible` | 100% |

- **三项都是定位符，不是路由**（单文件版）：`首页 → 第 1 屏`、`作品 → 第 2 屏`、
  `关于我们 → 末屏`（联系 + 泡泡池）。`<a href="#home|#works|#contact">` 对应三个 `.screen` 的 id，
  点击时 `preventDefault()` 后由 `goto()` 平滑滚过去（`scrollTo({behavior:'smooth'})`），
  再用 `history.replaceState` 把 `#home/#works/#contact` 写回地址栏 —— 用 replaceState
  而不是写 `location.hash`，是因为后者会触发浏览器自己的「跳到锚点」，把平滑滚动顶掉。
  首帧读同一个 hash 直接落位（`__bootNav`），刷新 / 分享回到同一屏。
  > 原来的 `#/studio ↔ #/works` 极简路由与「作品页牌堆」**已整体删除**：
  > 作品只有「第 2 屏点击卡片就地展开作品集」这一条路径。
- **高亮来源只有一个**：`syncCurrent()` 看哪一屏的顶边越过「视口 35% 线」，
  给对应的 `[data-goto]` 加 `aria-current`（其余删掉）。35% 而不是 50%：
  满屏吸附下 `scrollY` 正好落在屏顶，35% 让高亮提前半拍切过去。
  三屏各有一项，不再有「没有导航项的末屏」。
  平滑滚动途中用 `lockUntil`（760ms）屏蔽滚动反推，避免刚点亮的那项被改回去。
- **作品集展开时点别的屏**：`goto()` 先调 `window.__WS.leave()` —— 按既有退场动效
  退出作品集（缩小组原样下沉淡出、列表与图片流移回宿主），再滚动；
  入场动画还没走完则直接清掉定时器取消。点「作品」自己（i===1）不退出。
- **用 `opacity` 而不是改字色**。「整体」意味着 EN 小标（`--mute`）与 CN 中文（`--ink`）要一起变淡；改父级 `color` 传不下去——两个子元素各自带字色，父级改色对它们无效。
  > Next 版原来写的是 `active ? "text-ink" : "text-mute"`，而子元素各自 `text-mute` / `text-ink`，所以那套 class 一直是**空转的**，两态在页面上看不出差别。换成本次这套才真正生效。
  > Next 版仍走路由：由 `usePathname()` 推导后传给 `SwipeLink`（它 `{...rest}` 透传）。
- **hover 取 75% 而不是 100%**：直接跳到 100% 会被误读成「这个已经选中了」；75% 只表示「可点」。触摸设备没有 hover，不受影响。
- ⚠ 加这条时踩过一个坑：`.menu a` 上原来那句 `color:var(--mute)` 是 CN 中文**唯一**的字色来源。改成 `opacity` 后它被删掉，`.menu .cn` 就退回了浏览器默认的链接蓝。现在 `.menu .cn` 显式写 `color:var(--ink)`——验收里有一条断言专门盯这个。
- ⚠ **三项在窄屏会贴边**：`.menu .cn` / `.en` 都写了 `white-space:nowrap`（否则
  「关于我们」会被折成「关于我 / 们」两行），并在 `≤479.98px` 同时把 `.menu` 的
  `gap` 归零、`.menu a` 的内边距收到 `.3rem`。实测 1440 / 1024 / 768 / 390 / 360 / 320
  六档菜单右缘都还在 `--pad` 以内（360 下 345 / 360、320 下 304 / 320）。
- ⚠ 首屏导航浮在 3D 图片环之上（hero 不铺黑幕），环转到亮色卡片经过时会削弱对比，这是原有取舍、不是本次引入的。常规档下 EN 小标只有 25% 有效透明度，若嫌太淡，把 `.menu .en` 的 `--mute` 抬到 70% 白即可（有效 35%）。

## 十、部署相关的几个约定

- **发布源**：站点根 = `taste-design.html` + `ring/ works/ card-3d/ partners/` + `/v1/`。
  单文件版的资源引用全是相对路径，挂在 `/taste-design/` 子路径下**不需要任何前缀改写**，
  所以工作流里没有 `basePath` 注入这一步。
- **改仓库名**：只需保证仓库名与 Pages 地址一致；单文件版内部没有写死任何绝对路径，无需改代码。
- **发布前校验**：工作流会核对素材目录是否存在、HTML 里写死的相对路径是否都能取到文件，
  任一不满足即失败，避免发出缺图的半成品。
- **Next 源码不再参与发布**：`taste-design/` 保留作后续重构基础。若要让 Next 重新上线，
  先按「双交付」把分叉补齐（泡泡池、卡片长卷状态机），再改回 `npm run build` + `out/` 发布。

## 十一、素材

`logo/`、`works/` 是**真源**，`taste-design/public/` 与 `assets/` 下各有一份同步副本。
另有两组是**派生缩略图**（只为网页加载，不归档进 `assets/`）：

- `ring/` —— 40 张 640×457（1.4:1），从 `works/` 里均匀抽样后居中裁切；
- `card-3d/` —— 7 张 800×1200（2:3），从 `assets/card/` 的 1000×1500 等比缩到 800 宽（q82，合计 542KB）。

真源素材一律**原样拷贝**：不做降采样、不裁切、不抠底、不内联 base64——包括 logo 的 color 版自带白底也保留。

末屏泡泡池用的 `partners/`（14 张 1000×1000，白字透明底）同样原样引用，**不内联 base64**。
它们在球上要按 alpha 包围盒裁一刀再缩放，包围盒比例硬编码在 `taste-design.html` 的 `BOX` 里
——换图时如果新图的留白比例不同，重跑一次包围盒统计（`PIL`：`Image.split()[-1].getbbox()`）并同步 `BOX`。

**标签页图标** `favicon.ico` 同理原样引用（**多尺寸 PNG-in-ICO，7 层：16/24/32/48/64/128/256**，不重制），
同一个文件放两处：
根目录给 `taste-design.html` 同级引用（`<link rel="icon" href="favicon.ico" sizes="any">`），
`taste-design/public/favicon.ico` 给 Next 版（导出后落在 `out/favicon.ico`，线上即 `/taste-design/favicon.ico`）。
⚠ 多尺寸的意义：浏览器按设备像素比自取最合适的一层——1× 屏取 16、2× 屏取 32——都落在原生像素上，
不做拉伸。**若只含 16 一层，Retina 屏把 16 放大一倍绘制会明显发糊**，所以要换图标时务必换多尺寸版。
⚠ 内含的各层必须是**同一裁切**的多档尺寸；拿两个裁切不同的图硬合进一个 ico，切换尺寸时图形会忽大忽小。
⚠ Next 版**不要**用 `metadata.icons`：手写绝对路径不会被 `basePath` 自动改写（`assetPrefix` 只管 `_next/*`），
所以是在 `layout.tsx` 的 `<head>` 里写 `` href={`${BASE}/favicon.ico`} ``——同 §九 那条约定。

## 十二、字体：钉钉进步体（中文 + 英文统一）

站内**所有**中英文都走同一个家族 `钉钉进步体`（`--f-en` / `--font-display` 的唯一首项）。
后面跟的系统字体栈（苹方 → 冬青黑 → 黑体-简 → 雅黑 → 思源黑体）只是兜底。

- **只有一档字重（400）**：所以 `body` 上显式写了 `font-synthesis:none` ——
  站点里那些 `font-weight:500/620/650` 不会再被浏览器描边成「假粗体」。
  假粗体在中文上尤其难看（笔画糊成一团），宁可不加粗。
  **层级改由字号、字距、颜色承担**；`.display` 里原来给 Agile 用的
  `font-variation-settings:"SRIF" 0` / `font-stretch:97%` 已一并删掉（静态字体上没有意义）。
- **子集化**：原 ttf 2.0MB / 7526 字形，直接上网页不现实。`tools/build-fonts.py` 扫一遍
  `taste-design.html` + `taste-design/src/**/*.{ts,tsx,json}`，把所有出现过的字符（1002 个汉字 + ASCII + 常用标点，
  共 1180 个）交给 `fontTools.subset`，去 hinting、转 woff2 —— **139KB**（base64 后 185KB）。
- **单文件版内嵌 base64**：`taste-design.html` 里那个 `@font-face` 的 `data:font/woff2;base64,…` 由脚本写入
  `/* ▼▼ DINGTALK-FONTS:START … ▲▲ DINGTALK-FONTS:END */` 之间，**不要手改这一段**。
  这样双击 HTML 就能看到正确字形（不依赖同目录字体文件、也不吃 `file://` 的跨域限制）。
  代价是 HTML 约 324KB（gzip 后更小）。
- **Next 版走 webpack**：woff2 落在 `taste-design/src/fonts/DingTalkJinBuTi.woff2`，
  `globals.css` 里用相对路径 `url("../fonts/…")` 引，构建后输出到 `/_next/static/media/`，`basePath` 自动生效（同 §九）。
- **改文案出现新汉字时重跑脚本**，否则新字会退回系统字体（不会变豆腐块，但字形不统一）：
  ```bash
  /Users/chenyuan/.workbuddy/binaries/python/envs/default/bin/python tools/build-fonts.py
  ```
  源字体默认读 `~/Downloads/钉钉进步体0111/DingTalk JinBuTi.ttf`，
  换位置用 `FONT_SRC=/新目录`（或 `FONT_FILE=新文件名`）覆盖。
- **历史留档**：更早用过 Alimama Agile VF（可变字体，`font-weight:100 700` + `font-stretch:75% 125%`）
  与白无常可可体（三档静态）；`taste-design/src/fonts/AlimamaAgileVF-Thin.woff2` 留在仓库里只为回滚时不必再找文件，
  当前**没有任何规则引用**它。
